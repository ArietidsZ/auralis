## V02 产品与设备门

性能目标是本项目设计预算，不是当前实测结果。样本记录设备型号、OS、RAM、温度状态、runtime/模型 revision、EP、量化、线程数、是否冷启动；公布样本数和 p50/p95，不用全局均值掩盖慢请求。

| 指标 | 初始目标 | 测量边界 |
|---|---|---|
| 点录音到视觉反馈 | p95 ≤100ms | 点击时间至首帧状态反馈 |
| streaming 首个 partial | p50 ≤1.5s，p95 ≤3.5s | speech onset 到首个非空 partial；只用于真 streaming 模式 |
| 交替传译首段译文 | p95 ≤5s | speech end 到首个真实译文；单独报告输入时长 |
| TTS 首段音频 | p95 ≤1.5s | 译文提交到第一段可播放 PCM |
| TTS RTF | p95 ≤1.0 | 合成耗时/生成音频时长，排除播放等待 |
| 停止反馈 | p95 ≤100ms；音频停止 ≤500ms | UI 立即响应，native 资源只在安全时释放 |
| UI 帧 | 60Hz 设备 p95 ≤16.7ms | 活跃会话与长 transcript journey |
| 持续运行 | 20 分钟无崩溃、无限队列或持续内存增长 | 冷/热各采样，报告峰值 RSS/PSS 和系统热状态 |

初次建基线至少每模式 30 条短中长语句；确认回归至少 100 条；方言质量集至少覆盖普通话、粤语、吴语、闽南、四川及噪声/夹杂外语。用户声音样本不进入公开 CI。

ASR 输出 CER/WER 相对参考的绝对百分点变化；MT 人工记录漏译、错译、否定/数值/专名错误；TTS 记录可懂度、错误语言和克隆一致性。晋升阈值在有基准后固定，不能因某候选失败临时放宽。

设备缺失时仍必须完成测量入口与用例，但将真机门标 blocked，不能引用服务器性能填表。

## V03 必做消融

设计阶段已执行的结构消融见 evidence.md。实现后以下候选有代码/环境时进行对照；缺条件记录 blocked，保持简单基线。

1. 一个计算 worker vs ASR/MT/TTS 重叠：相同语句、线程总预算、热状态；只有 p95 端到端至少改善 10%、质量无退化且内存/热不更差才保留重叠。
2. CPU 基线 vs 可用 EP：记录图分区、CPU fallback、p95、峰值内存；无稳定收益则删除自动 EP 猜测。
3. MT cache 关闭 vs 有界 cache：先检验上下文/语种隔离，再测重复语句；非重复负载不能明显退化。没有收益可删除 cache。
4. MT/TTS native 共用 vs 两个后端：核实目标小模型/克隆/OS，测包体和生命周期复杂度；没有对应产物不得选前者。
5. 自定义 UI/状态包装 vs 原生控件/直接 controller：删除只转发一层的实现，运行相同状态与无障碍测试。
6. 默认高级音频/双模型流式 ASR 关闭：当前平台音频和单模型达标则删除额外音频 runtime/第二识别器提案。

对照一次只改一个因素；同一设备交错执行，保留原始测量。若两个方案差异小于测量噪声或均未通过正确性门，选择更简单且正确的方案，后者不得标记性能目标已达。
