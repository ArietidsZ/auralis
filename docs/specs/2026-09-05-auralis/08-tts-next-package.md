# TTS 下一版包与客户端接入（设计中）

本增补以实际数值实验为前提。当前 shared/tts.json 仍是 API contract 1、draft；以下包未安装为默认，不沿用旧包的验证状态。

## 选择依据

- 正确的重复惩罚与默认采样下，全量 INT8/INT4、三种分阶段量化均未通过事前固定的音色门。暂时保留 FP32，不以修改阈值或删除难例换取提速。
- 原始 decode 图可以 past 长度 0 起逐 token 预填，10/98/116 行与原 prefill 的 58 项输出数值一致。但 100 多行参考上下文的预填约慢十倍，不能作统一部署方案。
- 目标是一个真正支持动态输入序列长度和空/非空 past 的 FP32 talker 图。它应同时承担批量预填和单步生成，避免保留两份相同权重或每轮释放再加载。数值和真实生成通过前不替换。
- 官方 ICL 用参考文本与参考声码补充 speaker embedding。固定两人中英四对比较有声纹收益，且无新增可懂度失败；这只是功能准入证据。参考 encoder 已有真实 ORT 数值原型，后续仍须扩大独立质量集。
- 状态流式 vocoder 已有真实 ORT 图。参考 codes 先输入以准备因果状态，丢弃对应参考 PCM，再连续提交新语音。不会拼接独立截窗或回放参考录音。

## 模型包边界

下一包拟使用 manifest schema 2、TTS apiContractVersion 2。不要把 manifest schema 版本与模型 I/O 协议版本混在一起。

必要角色：speaker encoder、统一 talker、code predictor、参考 codec encoder、状态 vocoder，以及 tokenizer/embedding 支持文件。所有图、外部权重、支持文件都有独立大小和 SHA-256；角色指向包内文件。图的输入/输出 dtype、shape、状态初值和版本构成固定协议。

优先从单个固定的官方 Qwen checkpoint 编译完整包，避免把社区导出和官方新图拼成无法复建的多来源包。若完整单源导出尚未验证，则继续使用独立实验目录，不能为新增图虚构现有 HF revision 下的下载路径。

构建工具必须记录全部原始文件摘要、官方源码 revision、导出工具摘要、精确依赖版本和输出摘要。获取/构建只能调用仓库内预先审计的固定流程，manifest 不携带可执行命令。新派生字段需同时更新 Python、Kotlin、Swift 和共享 fixtures 后才可发布。

## 参考条件

原始录音保留为事实来源。参考文本须来自该录音的真实 ASR 或用户确认的文本；不能把提示词、目标译文或占位字符串当参考转录。派生 codes/embedding 的缓存键必须包含录音内容摘要、实际采样率及模型协议/权重身份。

缺少可验证参考文本时保留明确的 xvector-only 能力，不假称 ICL。用户界面不暴露图、张量或 cache 参数，只显示声音准备状态及失败原因。

参考 encoder 接收真实 24 kHz PCM；旧录音按其真实采样率转换。当前 sherpa 与 soxr 连续信号很接近，离散 VQ codes 仍会受边界影响，因此移动端 ICL 的可懂度和身份需要实际再验，不能引用同 PCM 的图对拍替代。

## 生成与播放

生成器按完整 16-codebook 帧向一个有背压的 sink 交付；sink 接收独立所有权的数据，失败或取消必须传回生成器。部分帧不是 EOS 或完成标记。

客户端保存有界 vocoder state。每块成功后才替换输入 state 并提交 PCM；失败块的全部输出丢弃。新句的普通模式 position/state 清零，ICL 则复用参考准备阶段的不可变初始 state。不能混入其他声音或其他模型版本。

ICL 的参考 warm-up 放在声音准备阶段，保存不可变的初始 state（约 5.2 MB）；每个 turn 从该快照创建独立工作 state。缓存归当前引擎/准备好的声音所有，不用全局 profileId 缓存。快照须绑定录音/参考文本与模型身份，输入和输出禁止原地复用；取消或失败不能污染下次 turn 的起点。本机首次组合实验每次重算参考上下文约 2 秒，因此每 turn 重算没有必要。会话释放时同时释放快照及原生句柄。

播放器在一个会话内连续接收 PCM，等待空间形成背压；禁止丢音频块来隐藏计算不足。停止需停止输出、取消生成、等待在飞原生调用、释放 tensor/session，再允许下一会话。已经播放部分内容后失败仍为失败/部分结果，不回填完成。

## 验收与消融

1. 原始两图与统一图：10/98/116 行真实预填、空 past/已有 past、完整 KV/hidden/logits、同采样下的 codes、音频和 ASR；不能只验证 graph 能加载。
2. 原整段与流式：多块长输入、跨注意力窗口、尾块、取消/重置、状态字节上界、整个连续 PCM 数值误差；禁止只看采样数和非静音。
3. ICL 与 xvector：固定参考/转录/目标文本、同 backend 与采样配置，独立参考与 held-out 声音；全部失败保留。量化若重开，必须相对新的正确 FP32 基线重新满足事前门。
4. 同硬件短串行窗口比较冷/热加载、生成、首个明确能量阈值音频可用时间、峰值和完整音频 RTF。并行高负载数据只作诊断。实际播放还需测欠载，离线推算的最小预缓冲不是设备实测。
5. 首批安静 PCM 不算可听首音；speaker/模型准备时间另列，不能从端到端延迟中悄悄删除。

只有完成上述工程检查、代表性质量集和实体设备门后才讨论 verified。当前主机、Catalyst 和模拟器证据均分别标注。
